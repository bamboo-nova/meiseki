# `.meiseki.json` の設定例

Jev 高速判定層へテキストを送ってよいかを、プロジェクトごとに決める設定ファイルの例です。同じフォルダの [`.meiseki.json`](./.meiseki.json) を、使いたいプロジェクトのルートにコピーして使います。

```json
{
  "jev": {
    "meiseki": "ask",
    "yorisoi": "ask"
  }
}
```

この例では、meiseki と yorisoi のどちらも、送る前にユーザーの確認を取ります。同意したときだけ送ります。

送った文章の保持を避けたい場合は、TypeSafe に申請して組織の ZDR(ゼロデータ保持)を有効にできます。無料で、どの組織でも申請できます。そのうえで送るかどうかを都度選べるように、この例では `ask` にしています。ZDR を有効にしていない場合や、外部へ一切送ってはいけない文書を扱う場合は、`deny` にするか、下の「設定ファイル以外で止める方法」を使ってください。

## 置き場所と読まれる順

`scripts/jev-judge.js` が、次の順で探して最初に見つけたものを使います。

1. 作業ディレクトリから親へ順にさかのぼって見つけた `.meiseki.json`
2. ユーザー全体の設定 `~/.config/meiseki/config.json`（書き方は同じ）
3. どちらもなければ既定値（meiseki=allow、yorisoi=ask）

## 値の意味

| 値 | 動き |
|---|---|
| `allow` | キーが設定されていれば、確認せずに送る |
| `ask` | スキルがユーザーに確認し、同意を得たときだけ送る。確認できない環境（CI・自律実行）では送らない |
| `deny` | 同意があっても送らない |

スコープの意味は次のとおりです。

| スコープ | 送る内容 | 既定値 |
|---|---|---|
| `meiseki` | 指摘箇所の文・段落の抜粋と質問 | `allow` |
| `yorisoi` | 文書の先頭 48,000 文字（ほぼ全文） | `ask` |

## ほかの書き方

すべてのスコープで送らない場合は、値を 1 つだけ書きます。

```json
{ "jev": "deny" }
```

スコープを 1 つだけ書くこともできます。

```json
{ "jev": { "yorisoi": "deny" } }
```

書いていないスコープ（この例では meiseki）は、さらに親フォルダの `.meiseki.json`、ユーザー全体の設定の順に探され、どこにもなければ既定値になります。

JSON として読めないファイル（末尾のカンマ、コメントなど）は、エラーを出さずに無視されます。設定が効いていないと感じたら、下の `--policy` で確かめてください。

## 設定を確かめる

プロジェクトのルートで次を実行すると、どの設定が効いているかが分かります。テキストは送りません。

```bash
node <meiseki のパス>/scripts/jev-judge.js --policy --scope yorisoi
# {"scope":"yorisoi","policy":"deny","source":"/path/to/project/.meiseki.json","key_configured":true}
```

## 設定ファイル以外で止める方法

- プロジェクトのルートに空の `.meiseki-no-jev` ファイルを置く。親へさかのぼって探されるので、リポジトリ全体で止まる
- 環境変数 `MEISEKI_JEV_DISABLE=1` を設定する（セッション・CI 単位）

どちらも `.meiseki.json` より優先され、何も送りません。
