# rikai 適用例

`rikai` が技術文書から論点を抽出し、別角度で復習しながら、学習状態・explainer・書き手向けの還流レポートを残す例です。題材の `sample-doc.md` と、その資料に対応する `.rikai/` フォルダの生成物を置いています(生成物は資料と同じ階層の `.rikai/` フォルダに入ります)。

| ファイル | 内容 | 見どころ |
|---|---|---|
| `sample-doc.md` | 通知配信ワーカーの再送設計 | 主張・前提・例外を含む 47 行の技術文書 |
| `.rikai/sample-doc.study.md` | 数セッション分の学習履歴 | 3 状態、別角度の再出題、誤答後の次セッションでの再挑戦、還流レポート |
| `.rikai/sample-doc.explainer.html` | 絵解きノート | 挑戦済みの論点を、大きな絵とひとことのたとえで振り返る。単体で開ける |
| `.rikai/sample-doc.explainer.pdf` | テキストブック | 定義と例題で細部を詰める。原稿は `sample-doc.explainer.tex` |

## 抽出した論点

現行の資料から抽出した論点は 7 個です。`topic-008` は旧版で抽出した論点であり、アンカー切れを示すために履歴へ残しています。

| 論点 id | 種別 | 判断する内容 | サンプル内の状態 |
|---|---|---|---|
| `topic-001` | 主張・前提 | 同じ一意キーの要求では新しいジョブを作らず、既存ジョブの ID を返す | 復習中 |
| `topic-002` | 例外 | 受付順で保存しても、配信の完了順は保証しない | 卒業 |
| `topic-003` | 主張 | `502`、`503`、接続タイムアウトを一時的な失敗として再送する | 復習中 |
| `topic-004` | 例外 | `429` は、再送しない `4xx` の通常則から除く | 卒業 |
| `topic-005` | 上限 | 再送前の待機時間を延ばし、8 秒を上限とする | 卒業 |
| `topic-006` | 前提 | 成功応答と応答 ID の保存がそろった時点で完了とする | 復習中 |
| `topic-007` | 手順 | 通常停止では送信中の要求の応答を記録してから停止する | 卒業 |
| `topic-008` | 旧版の論点 | 原文から削除された保守時間の規則 | 要再抽出 |

## 再現方法

履歴のない状態から動作を確認するときは、`sample-doc.md` だけを別の作業用ディレクトリへ複製し、そのファイルを指定してスキルを発動します。サンプルの `.rikai/sample-doc.study.md` を残したまま発動すると、既存履歴から復習キューが復元されます。

> 再現方法：プラグインを読み込んだ対話環境で、次のように依頼します。
>
> ```text
> meiseki:rikai を使って examples/rikai/sample-doc.md の理解度を確認して
> ```

問題は全問が 1 ページのフォームにまとまり、ブラウザで開きます。全問に答えて提出すると、採点結果の表がターミナルに出て、explainer が更新されます。誤答した論点は同じセッションでは再出題されず、次の起動時に優先して出題に含まれます。出題の順番は無作為で、どれが復習問題だったかは採点結果の表で分かります。

## 別角度の履歴の見方

論点「一意キーと重複の防止」は最初のセッションで誤答し、次のセッションで再挑戦しています。1 回目は同じ一意キーを受け付けたときの処理を直接選ぶ「主張の識別」、2 回目は一意キー `K1` を使った場面を判断する「具体例への適用」、3 回目は重複防止を成立させる「前提条件」です。問題文、観点、選択肢の判断内容が変わっているため、語順や正答位置だけを変えた反復ではありません。

`topic-002` は途中に誤答を挟みながら `correct: true` が通算 3 件に達したため卒業しています。途中の誤答で正解回数はリセットしていません。`topic-004`、`topic-005`、`topic-007` は誤答がないため、最初の正解で卒業しています。

## study.md の読み方

YAML frontmatter が機械の使う正本です。`source_path` は対象資料、`topics` は論点、`anchor` は見出しパス・原文冒頭の引用・参考行番号、`attempts` は古い順の挑戦履歴を表します。各履歴には、問題文、観点、提示順の選択肢、回答、セッション識別子が入っています。`reasoning` は以前の方式で記録した誤答理由です。新しい記録では常に `null` になります。

各論点には人が読める `title`(題名)が付きます。論点の解説は study.md には書かれず、絵解きノートとテキストブックにまとまります。`status` が `復習中` の論点は次回以降の出題対象、`卒業` は出題対象外です。誤答のない論点は最初の正解で、誤答を経験した論点は通算 3 回の正解で卒業になります。`要再抽出` はアンカーが原文と一致せず出題対象外です。論点「旧版・保守時間」の古い見出しと引用だけは、アンカー切れの例として意図的に `sample-doc.md` と一致させていません。

本文末尾の「書き手への還流レポート」は、誤答をアンカー単位で集計したものです。誤答回数の降順、最終誤答日時の降順、論点 id の昇順で並び、卒業または要再抽出の論点に残る誤答も集計します。この例では 5 段落に合計 6 件の誤答があります。
