# study.md の形式

## 1. ファイルの役割

`study.md` は、機械が復元する状態を YAML frontmatter に、書き手向けの還流レポートを Markdown 本文に持つ。状態の正本は frontmatter であり、本文から挑戦履歴や状態を逆算しない。論点の解説は study.md に書かず、同じフォルダの explainer（絵解きノートとテキストブック）に書く。

ファイルは対象資料と同じ階層の `.rikai/` フォルダに置く(資料一覧を汚さないため)。資料名が `.md` で終わる場合は末尾の `.md` を `.study.md` に置換し、それ以外は元のファイル名に `.study.md` を追加する。旧配置(資料の隣に直置き)のファイルは読み込み時に `.rikai/` へ移す。

## 2. frontmatter スキーマ

最上位には `schema_version`、`source_path`、`topics` を置く。

| キー | 型 | 必須 | 規則 |
|---|---|---|---|
| `schema_version` | 整数 | 必須 | 現行値は `3`。`1` と `2` の既存ファイルは、§4.1 の手順で読み込み時に `3` へ移行する |
| `source_path` | 文字列 | 必須 | `study.md` から資料への相対パス。`.rikai/` 配置では通常 `../資料名` |
| `topics` | 配列 | 必須 | 論点オブジェクトの配列。0 件でも空配列を置く |

各 `topics[]` は次のキーを持つ。

| キー | 型 | 必須 | 規則 |
|---|---|---|---|
| `id` | 文字列 | 必須 | `topic-NNN` 形式で資料内一意。削除した id は再利用しない |
| `title` | 文字列 | 必須 | 人が読んで内容が分かる短い題名(例「RPO と RTO の区別」) |
| `anchor` | オブジェクト | 必須 | 原文段落を指すアンカー |
| `status` | 文字列 | 必須 | `復習中`、`卒業`、`要再抽出` のいずれか |
| `attempts` | 配列 | 必須 | 挑戦履歴を `attempted_at` の昇順で並べる。未挑戦なら空配列 |

各 `anchor` は次のキーを持つ。

| キー | 型 | 必須 | 規則 |
|---|---|---|---|
| `heading_path` | 文字列の配列 | 必須 | 最上位から直近までの見出し本文。見出し記号は含めない |
| `quote` | 文字列 | 必須 | 根拠段落の冒頭に前方一致する原文。要約しない |
| `line` | 整数または `null` | 必須 | 取得時の 1 始まりの参考行番号。行番号を得られない資料は `null` |

`heading_path` と `quote` の組をアンカーの主キーとする。照合時は改行コードを統一し、段落外側の空白だけを除いて前方一致を確認する。句読点や語句を正規化して一致したことにしてはならない。組に一致する段落がない場合や複数段落に一致する場合は、`line` が合っていても `status` を `要再抽出` にする。

各 `attempts[]` は次のキーを持つ。

| キー | 型 | 必須 | 規則 |
|---|---|---|---|
| `attempted_at` | 文字列 | 必須 | タイムゾーンを含む ISO 8601 日時。例 `2026-09-22T09:00:00+09:00` |
| `correct` | 真偽値 | 必須 | 正答は `true`、誤答は `false` |
| `question` | 文字列 | 必須 | 実際に提示した問題文 |
| `aspect` | 文字列 | 必須 | 問うた観点。例 `適用条件`、`例外条件` |
| `choices` | 配列 | 必須 | 実際に提示した順序の選択肢オブジェクト。2 件以上 |
| `user_answer` | オブジェクト | 必須 | ユーザーが選んだ選択肢と、理由欄 `reasoning`(新しい履歴では常に `null`) |
| `session_id` | 文字列 | 必須 | セッション内で共通の空でない識別子 |

各 `choices[]` は文字列の `id` と `text` を持つ。`id` は同じ問題の中で一意にし、画面に提示した番号または記号をそのまま記録する。

`user_answer` は文字列の `choice_id` と、文字列または `null` の `reasoning` を持つ。`choice_id` は `choices[].id` のいずれかと一致させる。`reasoning` には常に `null` を書く。誤答の理由は尋ねず、記録もしない。以前の形式で記録された文字列は、書き手への還流に使えるので、そのまま残す。

## 3. 状態遷移と保存

状態の値 `復習中`、`卒業`、`要再抽出` は機械が照合する決まった文字列であり、ユーザーの言語によらずこのとおりに書く（explainer では、ユーザーの言語に訳して表示する）。論点の初期状態は `復習中` とする。卒業の条件は誤答経験の有無で分かれる。`correct: false` が 1 件もない論点は、最初の `correct: true` を保存した時点で `卒業` にする。`correct: false` を含む論点は、`correct: true` が通算 3 件に達した時点で `卒業` にする。`correct: false` が途中にあっても正解件数を減らしたりリセットしたりしない。

アンカーが切れた論点は `要再抽出` にし、出題対象から外す。原文から論点とアンカーを再抽出できた場合だけ、内容を確認して `復習中` に戻す。

提出された回答の採点が終わった時点で `attempts` を追記し、状態を再計算して frontmatter と本文を保存する。保存は 1 セッションに 1 回である。`attempted_at` には回答ファイルの `submitted_at` を使う。回答ファイルがない場合は、採点した時刻を使う。出題する論点がなかったセッションでも、アンカーの照合で状態を変えた論点があれば、explainer を更新する前に保存する。

## 4. 人が読む本文

本文（導入と還流レポート）は、ユーザーの言語によらず日本語で書く。

frontmatter の後には `# 学習記録` を置き、その直後に「このファイルの読み方」の導入を数文で書く。導入には次の 4 点を含める。初見の読者が予備知識なしで読めるようにするためである。

- このファイルが rikai スキルの学習記録であること
- 論点とは、資料から抽出した出題単位であること
- 状態 3 種(復習中・卒業・要再抽出)の意味
- 解説は同じフォルダの explainer にあり、このファイルの本文には還流レポートだけを置くこと

本文には論点ごとの解説や図を書かない。`topic-NNN` の id は機械照合用の内部キーであり、本文には表示しない。

本文の末尾には見出し `## 書き手への還流レポート` を一つだけ置く。更新時はこのセクション全体を再生成し、古い集計結果を追記で残さない。

### 4.1 以前の形式からの移行

`schema_version` が `1` または `2` のファイルを読み込んだら、次の順に直して保存する。

1. `schema_version` を `3` にする。`1` のファイルは、各論点に `title` を補う。
2. 本文の `# 学習ノート` を `# 学習記録` に変え、導入を上の 4 点に合わせて書き直す。
3. 本文から、論点ごとの見出し(`### 題名`)とその内容、未挑戦の論点の一覧、mermaid のコードブロックを取り除く。
4. frontmatter の `topics` と `attempts` は変更しない。`reasoning` に入っている文字列も消さない。
5. 還流レポートを §5 の規則で再生成する。
6. この資料の以前の方式の PDF（`.rikai/<資料名>.study.pdf`）は、ここでは扱わない。もう更新しないことと、削除してよいかは、セッションの終わりの報告（SKILL.md の Step 7）でまとめて伝える。

挑戦済みの論点の解説は、移行した回のセッションの終わりに explainer へ書く。

## 5. 還流レポートの集計規則

還流レポートは、すべての論点の `attempts` から `correct: false` だけを取り出し、アンカーの主キーである `heading_path` と `quote` の組が同じ履歴を一つの段落として集計する。状態が `卒業` または `要再抽出` でも、誤答履歴は集計から除外しない。

誤答が 1 回以上ある段落だけを列挙する。各項目には、その段落に結び付く論点の題名(複数あれば列挙)、誤答回数、最終誤答日時、見出しパス、引用文字列を表示する。id は表示しない。並び順の決定にだけ内部的に id を使い、段落に複数の論点がある場合は辞書順で最小の id をその段落のソート用キーとする。

並び順は、誤答回数の降順、最終誤答日時の降順、ソート用論点 id の昇順とする。日時は ISO 8601 の時点として比較し、表示上の文字列順では比べない。

末尾に全段落の誤答回数を合計した `誤答総数: N` を表示する。対象段落がない場合は項目を置かず、`誤答総数: 0` とする。

集計対象、グループキー、ソートキー、同率時の順序、合計の定義を固定し、同じ frontmatter からは常に同じ還流レポートを生成する。本文の自由記述、現在の行番号、処理時刻は集計や順序に使わない。

## 6. スキーマ確認チェックリスト

- [ ] YAML frontmatter がファイル先頭の `---` で始まり、対応する `---` で閉じている。
- [ ] `schema_version` が整数 `3` である。
- [ ] ファイルが資料と同じ階層の `.rikai/` フォルダにある。
- [ ] `source_path` が空でない文字列であり、`study.md` から資料を参照できる。
- [ ] `topics` が配列である。
- [ ] 各論点に `id`、`title`、`anchor`、`status`、`attempts` があり、余分な別名キーで置き換えていない。
- [ ] 各 `title` が空でない、人が読んで内容が分かる題名である。
- [ ] 各 `id` が `topic-NNN` 形式で、資料内で重複していない。
- [ ] 各 `anchor` に `heading_path`、`quote`、`line` があり、`heading_path` は文字列の配列、`quote` は原文冒頭の文字列、`line` は 1 以上の整数または `null` である。
- [ ] 各 `status` が `復習中`、`卒業`、`要再抽出` のいずれかである。
- [ ] 各 `attempts` が配列で、`attempted_at` の昇順に並んでいる。
- [ ] 各挑戦履歴に `attempted_at`、`correct`、`question`、`aspect`、`choices`、`user_answer`、`session_id` がある。
- [ ] 各 `attempted_at` がタイムゾーンを含む ISO 8601 形式の文字列である。
- [ ] 各 `correct` が YAML の真偽値 `true` または `false` である。
- [ ] 各 `question`、`aspect`、`session_id` が空でない文字列である。
- [ ] 各 `choices` が 2 件以上の配列で、すべての要素に文字列の `id` と `text` があり、同じ問題内で `id` が重複していない。
- [ ] 各 `user_answer` に `choice_id` と `reasoning` があり、`choice_id` は提示した選択肢の id と一致する。新しく書く履歴の `reasoning` は `null` である。
- [ ] 誤答のない論点は、正解が 1 件以上あれば `卒業`、未挑戦なら `復習中` である。
- [ ] 誤答を含む論点は、`correct: true` が 3 件以上なら `卒業`、3 件未満でアンカーが有効なら `復習中` である。
- [ ] アンカーが一意に照合できない論点は `要再抽出` である。
- [ ] 本文が `# 学習記録` で始まり、導入に 4 点(ファイルの説明・論点の説明・状態の意味・解説の置き場)がある。
- [ ] 本文に、論点ごとの解説・図・未挑戦の一覧がない。
- [ ] 本文に `topic-NNN` の id が表示されていない(id は frontmatter のみ)。
- [ ] 本文末尾に `## 書き手への還流レポート` が一つだけあり、集計項目、並び順、`誤答総数` が §5 の規則と一致する。

# 学習記録

このファイルは meiseki:rikai（読解度チェックスキル）が生成した学習記録です。資料「sample-doc.md」から抽出した論点（topic ＝ 出題単位。資料の主張・前提・例外のひとまとまり）ごとに、出題履歴と状態を frontmatter に記録しています。状態は 3 種類あり、復習中は今後も出題される論点、卒業は理解済みとして出題されない論点、要再抽出は原文の改稿で根拠箇所を見失った論点です。論点の解説は、同じフォルダの絵解きノート（sample-doc.explainer.html）とテキストブック（sample-doc.explainer.pdf。PDF がなければ原稿の sample-doc.explainer.tex）にあります。下の「書き手への還流レポート」は誤読が集中した段落の一覧で、資料の書き手が明晰化の入力に使えます。

## 書き手への還流レポート

1. 論点: 更新後の購読者通知
   - 誤答回数: 1
   - 最終誤答日時: `2026-09-22T11:00:00+09:00`
   - 見出しパス: `更新通知`
   - 引用: 「更新後は購読者へ通知を送る。」
2. 論点: 通常キャッシュの有効期限
   - 誤答回数: 1
   - 最終誤答日時: `2026-09-22T09:00:00+09:00`
   - 見出しパス: `キャッシュ方針 > 有効期限`
   - 引用: 「キャッシュの有効期限は通常 10 分とする。」
3. 論点: 障害対応中の TTL 短縮
   - 誤答回数: 1
   - 最終誤答日時: `2026-09-21T10:30:00+09:00`
